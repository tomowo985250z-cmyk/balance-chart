# LINK折衷順位 本番反映・回帰結果

2026-10-11。検証済み折衷方式を本番コードへ反映。ユーザーの画面確認後、関連ファイルのcommit・origin/mainへのpush承認を受け、公開前に16群23,197チェックを再実行して通過した。旧順位へ戻すUIや切替は追加していない。

## 実装

`link-ranking.js` は、両予測終点0.2 IPS以下→HOV予測終点0.2以下を最優先する。合格候補がない場合だけ、方向区分「両方中心向き → HOVのみ中心向き → 巡航のみ中心向き → 両方中心向きでない」を優先する。同じ区分内は既存の予測終点比較を使用し、HOV終点を厳密に比較、HOV同値なら巡航を比較する。合格候補間の最大距離→合計距離、0.2の厳密な境界、0.18の参考扱いは維持した。

`app.js` の候補正規化で、現在点と表示ガイドの単位ベクトルから中心接近の内積 `inwardProjection` を順位情報として追加した。半直線の最接近点・予測移動量・予測終点とは別の情報で、学習や予測距離を生成しない。接線を中心向きと扱わず、方向欠測は未知として最後に置く。接線近傍の丸め順序も検証済み試験と一致させた。

巡航距離欠測でも方向は評価可能だが、移動量・終点・改善量はnullのまま。両達成にはならず、既存の不確実性・欠測表示を維持する。全HOV終点欠測の場合も達成を捏造せず、方向区分内で安定したNo順の診断表示にする。

既存UI、調整量の保持・確定、No.1〜3切替、手動No・方向、TAB、ガイド・予測点描画、確定予測・表示キャッシュ、保存形式は維持した。`index.html` はJSのキャッシュ識別子だけ更新した。

`learning.js`、`distance-prior.js`、`app-state.js` のSHA256は実装前後で一致。実アプリの回帰で学習状態、同条件の予測出力、測定値、保存済み記録の不変性を確認した。

## No.1〜3の実画面検証

添付画像の近似条件、巡航0.33・時計5:30、共有量1/4、回転HOV -41°／巡航 -60°、学習未成立。端末の学習データを取り込んだ再現ではない。

| 現在HOV | 本番候補順位 |
|---|---|
| 0.32・時計角100° | No.1 UP → No.2 DOWN → No.3 DOWN |
| 0.19・時計角112.5° | No.2 DOWN → No.1 UP → No.3 UP |

改善後はNo.2／No.1のHOV合格候補が先に残り、合格候補がないNo.3は方向でUPを選ぶ。No.3 UPのHOV予測終点0.246796262／巡航0.161884188、HOV悪化量+0.056796262。DOWNのHOV終点0.241030340より0.005765922 IPS大きいが、方向区分が異なるためUPが先になる。

全Noで、フォームのNo・方向・共有量、順位評価の終点、SVGの矢印方向、表示予測点が一致した。No.3 UPには巡航予測点が表示され、改善前No.3 DOWNの巡航欠測では点を描かない。No.3選択中の測定改善でも順位・ガイド・予測点が同じNo.3 UPへ更新される。共有量1/4の保持に加え、本番回帰では学習済み／未学習・巡航測定有無と1/4／1/2量を検証した。

## 同一1,296条件の独立試験との一致

前回と同じ合成位置・回転・量・未学習条件を、変更前の独立終点順位 `LinkRankingPolicy`、試験内の折衷参照、本番の `BalanceLinkRanking` へ渡した。1,296条件すべてで本番と検証済み折衷参照の選択が一致した。

| 自動1位の指標 | 変更前の終点優先方式 | 本番折衷方式 |
|---|---:|---:|
| 両方0.2以下の予測を選択 | 676 | 676 |
| HOV 0.2以下の予測を選択 | 1,224 | 1,224 |
| 巡航予測欠測の候補を選択 | 180 | 184 |

1位変更17条件、すべてHOV合格候補なし。両達成・HOV合格の選択喪失は各0。巡航の新規欠測8件／欠測解消4件。変更17件のHOV終点は変更前より大きくなる。両方式で巡航終点が既知の1,108条件では、巡航終点・最大距離・合計距離の増加は各0。欠測条件はこれらの数値比較から除外している。

この件数は参考予測と合成位置による順位比較であり、実測達成率ではない。実測精度は未検証で、既存画面の注意表示を維持する。
