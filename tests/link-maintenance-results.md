## 追加検証：中心向き候補の既知終点と行き過ぎを評価

両達成予測の最優先、HOV0.2以内維持、巡航の中心向き優先を保ったまま、中心向き候補同士では既知の予測終点を幾何学的到達可能性・方向角より先に比較した。HOVの中心距離は圏内候補同士の順位に使わない。欠測を達成とせず、未測定の巡航も両達成予測に含めない。

- **既知終点優先**（`cruiseEndpointPolicy:'known-first'`）：既知終点を欠測より優先し、既知同士は小さい終点距離を優先。
- **改善予測優先**（`'improvement-first'`）：既知の改善・同距離 → 欠測 → 既知の悪化の順。既知同士は終点距離を比較。

同じ2,592合成条件・同じ指定量で比較した。全体にはHOV維持予測候補のない診断条件1,464件が含まれるため、実行候補の改善件数とはしない。

| 両達成予測を選択（全2,592条件） | 421 | 421 | 421 | 421 |

## 結果と評価方針

HOVが既に0.2 IPS以内なら、圏内候補同士のHOV中心接近量を優先しない比較方式を試験した。画像近似・未学習条件では、巡航の幾何学的到達可能性と方向角を評価すると、No.1 DOWN・1/8 flatが比較候補になる。HOV予測終点は0.140757で名目上圏内を維持するが、巡航予測終点は欠測。両方達成・合格確定・実調整推奨とはしない。

幾何重視だけを先行させると、合成2,592条件中80条件で、既存が選択した「両予測終点0.2以内」の候補を選ばなくなる。両予測が名目上圏内の候補を先に保護し、その集合内で幾何評価する比較案では、この喪失が0件になった。この比較案も実機での成功確率や合格を保証しない。

## 比較した方式

すべてHOV現在値が厳密に0.2以下のときだけ適用する。現在値が圏外なら既存選択へ戻す。境界の丸め・許容差拡張は行わない。全量比較と指定量ごとの比較を分ける。本番の共有調整量を自動変更する処理はない。

| 方式 | 比較順 |
|---|---|
| 現行 | 既存 `BalanceLinkRanking.select` をそのまま使用 |
| 方向符号優先 | HOV予測終点が圏内 → 巡航が中心向き → 同方向区分の巡航予測終点 |
| 幾何重視 | HOV予測終点が圏内 → 巡航が中心向き → 巡航の半直線が0.2へ到達可能 → 中心への方向角 → 巡航予測終点 |
| 両予測圏内保護付き | 両予測終点が名目上0.2以内の候補を先に保護し、その中で上記の方式を適用 |

HOV維持予測がない場合は、HOV予測欠測だが幾何学的に正の移動距離で維持可能な候補、既知の圏外予測などを順に診断表示する。欠測候補を既知の維持予測より上にしない。HOV圏内候補同士の中心距離・接近量・方向角・境界余裕は順位の比較項目にしない。巡航未測定の場合もHOV中心接近量は復活させず、少量・No.・UP/DOWNによる安定した比較順にする。

「中心向き」は現在点から前向き単位ベクトルへの内積で判定する。無限直線の後方交点は使わない。接線は中心向きに含めない。中心点は方向角が未定義でも、正の移動で圏内を維持できる。

距離推定・学習関数・実アプリの順位関数は差し替えない。予測は既存の `learning.predict` / `BalanceDistancePrior.resolve` / `getLinkRankingCandidates` から取得し、学習済みの場合は実際の学習予測ベクトルを使う。

## 予測・幾何学・実測の区別

- 名目上の維持・達成：既存の指定量の予測終点を厳密に `<= 0.2` で比較する。
- 幾何学的可能性：前向き方向線が圏内にある移動距離区間を持つ。調整量・移動距離の対応や達成確率は保証しない。
- 不確実性：prior・参考値・比例推定・欠測を維持。学習モデルが準備済みでも実機精度を確認したとは扱わない。
- 合格確定：全候補で `confirmedPass:false`、`realWorldValidated:false`、`confirmedRecommendation:null`。名目上の両圏内予測の保護を、実測合格の保護とは呼ばない。

HOV中心・接線・境界の隣接浮動小数点数・短い外向き移動・行き過ぎ・予測欠測・巡航未測定・既知の圏外予測を含む。幾何学の独立864条件では半直線の最短距離と、移動距離別の円内判定を検証。画像近似、前回条件、HOV中心、HOV境界、合成学習済み、巡航未測定の7条件群×全No.×UP/DOWN×9量＝378候補を記録した。

合成学習済み群は実際の確認・学習同期を通じてモデルを準備し、各予測の由来が `learned` であることを検証した。モデルの方向は合成履歴から学習したもので、画像の端末モデルではない。学習状態によって比較結果が変わることも確認した。
