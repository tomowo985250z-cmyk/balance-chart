# 学習・既存操作の回帰テスト

`dot-numbers.html?isolated=1` は14個の密集ドットで番号サイズ・重なり回避を検証する。
ピンチ中・指を止めている間・縮小中の相対位置保持、終了後の必要な再配置、touchcancel後の再開、
連続viewBox変更の待機、画面幅変更、単独番号の近さ、計算・予測・学習・保存データ（表示倍率を除く）の不変性も確認する。
専用ブラウザプロファイルで実行する。

`guide-numbers.html?isolated=1` はLINK No.1〜3／タブ No.1〜3を既存の優先順位で循環表示し、各Noの最適候補・方向・調整量・ガイド線・予測ドットの連動を検証する。
手動・自動条件待ち・学習済み、手動変更時の非表示、画面別の選択保存、旧4候補形式からの移行、320〜430px幅でのボタンの重なり・文字切れも確認する。

`guide-selection.html?isolated=1` はLINK/TAB・優先順位1〜3位で、調整量「1」「4」の自動値からの変更・復帰・確定・取消を検証する。番号とUP/DOWNの独立判定、および学習データの不変性も確認する。

`link-direction-priority.html?isolated=1` はLINK自動選択の新旧順位を比較する。
両色が中心へ近づく候補の優先、予測終点による行き過ぎ評価、巡航待ち、優先候補がない場合を確認する。
距離比較には仮定値を使い、画像の概算位置・角度は実際の未学習ガイド計算で3 LINK UPを確認する。
端末の学習値や実機の予測精度を再現するテストではない。

`initial-position.html?isolated=1` は画面ごとの初期位置登録、確認ダイアログのOK／キャンセル、未登録時の互換性、空の状態での再読込・ページ再作成、結果がある場合の最新位置維持、保存失敗を確認する。結果・調整量・予測・学習データを変更しないことも確認する。専用ブラウザプロファイルで実行する。

`guide-edge.html?isolated=1` は円を通らないガイド線の画面端への延長、円を通る線・接線の維持、画面外から入る線、描画更新時の候補・予測・学習・保存データの不変性を確認する。専用ブラウザプロファイルで実行する。

`guide-direction.html?isolated=1` は候補評価とガイド線の移動方向を検証する。優先順位1〜3位、LINK/TAB、手動・自動条件待ち・実際の学習モデル、圏内・境界・圏外、回転角を組み合わせる。HOV 1.80／4:50は実入力からHOV単独でも確認する。円との交点が後方にある場合の描画反転、学習済み候補の移動ベクトル評価、学習データと同条件の予測結果の不変性を検証する。専用ブラウザプロファイルで実行する。`&screenshot=1` を付けると最後に375px幅の重点条件を表示する。

`rotation-continuity.html?isolated=1` は調整量「1:」の手動変更・取消・再読込時の予測表示と、LINK/TABの最新角度の保持を検証する。学習済み／条件待ちの両方で、手動→自動→手動、ページ往復、再読込、SVG描画、学習データの不変性を確認する。専用ブラウザプロファイルで実行する。

保存・起動状態の回帰確認は`state.html?isolated=1`を専用プロファイルで実行する。
旧データ原本の非破壊、再読込、生成済み予測の座標保持、ファイル移行、競合・保存失敗を検証する。
手順とOS上の制約は[STATE-RESTORE.md](../STATE-RESTORE.md)を参照。

`forecast-lifecycle.html?isolated=1` は未確定プレビューの生成→表示用保持→復元→DOMを追跡する。
HOV 0.50 / 2:00、巡航 0.50 / 1:00、LINK 1/4、回転0度・学習履歴なしで再現できる。
1位はNo.3 DOWN（巡航の距離推定なし）、2位はNo.2 UP（巡航を生成可能）。
同じ測定・種別・No・方向・調整量の生成済み座標だけを表示専用メモリから復元する。
No.2の予測をNo.3には表示せず、予測計算・補正・学習データには混ぜない。
量・測定の変更と削除も検証する。初回から距離推定がなく未生成の場合に、座標を捏造する処理は追加しない。

`forecast-candidates.html?isolated=1` は実際のNo切替ボタンを使い、
手動・学習済みAUTOそれぞれで、LINKのHOV・巡航とTABの生成済みドットが
選択Noの予測座標どおりに描画されることを検証する。
調整量フォームで確定した後、No切替は新しいプレビューを表示する。
3候補の循環・回転・ガイドON/OFFでも、記録済み調整量・学習データ・保存済み測定が変化しないことも確認する。

予測ドット表示の回帰確認は、専用の一時ブラウザプロファイルで
`forecast-display.html?isolated=1` を開く。実際のアプリと距離計算を使い、
LINKのHOV・巡航とTABについて、生成済みドットがガイドの番号・方向不一致、
ガイド欠落、個別非表示でも保存座標で表示されることを確認する。
プレビュー・確定・比較表示、全体ガイドOFF、ページ切替、予測・学習・保存データの
不変性も検証する。実行方法は以下と同じ。

`learning.html?isolated=1` を、普段使うブラウザとは別の一時プロファイルで開く。
実画面の入力・削除・保存も検証するため、テスト専用の保存領域を使う。
HTTPで同一オリジンから配信するか、Edgeのヘッドレス実行では
`--allow-file-access-from-files --virtual-time-budget=15000 --dump-dom`
と専用の `--user-data-dir` を指定する。追加パッケージは不要。
結果はページの `PASS` / `FAIL` と確認項目数に表示される。

## 実装の確認ポイント

- `learning.js` はLINK/TAB × 赤/青の4モデルを独立管理する。
  最新結果への単一調整を「実調整として記録」で指定した場合だけ、次の新規測定を既存のXY変換で学習する。
  指定は毎回オフに戻る。練習入力・過去調整への後付け指定・測定編集は新たに学習しない。
  巡航の後入力は、指定済みの次回測定にまだ巡航がなかった場合に限り取り込む。
  複数調整の結果は原因を分離できないため対象外。
- 調整量で正規化した距離を使う。LINKのフラット数とTABの度数は混ぜない。
- 親モデルは3件（有効角度2件以上）、同じBLD/方向別モデルは2件から優先する。
  紫六角形の角度・ガイドはTAB→巡航だけを使用する。
  学習率0.60の指数重みで、最新60%、1つ前24%、2つ前9.6%相当を反映する。
  1件の角度更新は最大±13.5度。移動が0.02 IPS相当未満なら角度を学習しない。
  距離比は0.5～2、1回の予測距離更新は前回の0.85～1.3倍に制限する。
  距離の基準は更新するため、古い初回距離の倍率上限に張り付かない。
  これらは数値的な安定化の初期設定であり、実機精度を保証する値ではない。
- 学習データは別の `balance-chart-learning-v1` にversion 2形式で保存する。
  旧version 1の未確認データは実調整と推定せず、学習対象から除く。測定・調整・回転設定は保持する。
  保持中の測定履歴から再構成するため、再描画で件数は増えず、編集・削除も反映する。
  削除で新しく隣り合った結果は、新しい調整の実測として学習しない。
- 調整登録時の予測は固定して保存する。既存履歴から作る予測は
  `prospective: false` として区別する。
- 六角形の自動回転は、学習済み角度がなければ、実調整未指定でも直近の単一調整と前後測定を使用する。
  LINK赤・青、TAB紫は対象色と調整種別を独立して参照し、未指定履歴を学習・確定済みデータへ追加しない。
- LINK自動選択はHOV・巡航の実際の予測方向が両方とも中心へ近づく候補を優先する。
  その中で予測終点の中心距離の最大値、合計の順に比較し、行き過ぎも評価する。
  両色が中心へ近づく候補がない場合は全候補の終点距離で比較する。HOV単独の場合はHOVの方向・距離を使う。
  学習不足時も自動では同じ順位を使い、既存の移動距離予測・巡航待ち時の円周交点による代替を維持する。
  手動では従来のHOV 0.15制約・有向線通過・距離の順位を維持する。
  TABの評価対象は既存どおり巡航のみ。TAB→HOVの実測モデルも別に保持する。
- 学習リセットは測定・調整・回転設定を削除しない。
  リセット時点の連続結果を再学習せず、その後の新しい結果から学習を再開する。
- 手動補助は自動から手動に切り替えた後、実際に回転した色だけを記録する。
  実測モデルへの補助角度は小さく制限し、実測数が増えると影響を弱める。

開発者コンソールで `balanceChartLearning.inspect()` を実行すると、
モデル、実測ベクトル、記録時の予測、誤差、候補の予測終点・改善量、
フォールバック理由、保存エラーを確認できる。調整を自動で確定する機能はない。

## Cruise参考距離の母集団と分離

`distance-prior.js`の`blue`がCruise。LINKでは青、TABでは紫として表示する。
`red`はHOVであり、「赤LINKのCruise」という別母集団は存在しない。
既存の共通`resolve()`を使用し、learned → 完全一致prior/補正済みprior →
同色・同種別・同調整量の中央値（n>=2）→ 最近傍の学習済み調整量からの比例表示 → 非表示の順とする。
比例表示は対象量÷基準量を距離へ掛け、上下どちらの量にも適用する。同量の実測を取得した後は完全一致を優先する。
比例結果は表示専用で、学習データや実測母集団へ保存しない。
TABの直接参照値が1° < 2° < 3°にならない場合は、同じ系列・No.・方向の1°当たり距離の中央値で表示距離を正規化する。
十分な実測で成立した学習モデルは調整量で正規化済みのため従来どおり最優先し、LINKにはこの単調化を適用しない。
参考値だけNo./UP/DOWNを緩和する。ただし青LINKはUP/DOWNを分離し、No.だけ緩和する。
TAB HOVやテスト生成値を母集団へ追加しない。
参考距離・補正済み予測を実測として保存しない。
