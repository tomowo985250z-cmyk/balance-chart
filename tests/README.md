# 学習・既存操作の回帰テスト

`learning.html?isolated=1` を、普段使うブラウザとは別の一時プロファイルで開く。
実画面の入力・削除・保存も検証するため、テスト専用の保存領域を使う。
HTTPで同一オリジンから配信するか、Edgeのヘッドレス実行では
`--allow-file-access-from-files --virtual-time-budget=15000 --dump-dom`
と専用の `--user-data-dir` を指定する。追加パッケージは不要。
結果はページの `PASS` / `FAIL` と確認項目数に表示される。

## 実装の確認ポイント

- `learning.js` はLINK/TAB × 赤/青の4モデルを独立管理する。
  最新結果への単一調整を「実調整として記録」で指定した場合だけ、次の新規測定を既存のXY変換で学習する。
  指定は毎回オフに戻る。練習入力・過去調整への後付け指定・測定編集は新たに学習しない。
  巡航の後入力は、指定済みの次回測定にまだ巡航がなかった場合に限り取り込む。
  複数調整の結果は原因を分離できないため対象外。
- 調整量で正規化した距離を使う。LINKのフラット数とTABの度数は混ぜない。
- 親モデルは3件（有効角度2件以上）、同じBLD/方向別モデルは2件から優先する。
  紫六角形の角度・ガイドはTAB→巡航だけを使用する。
  学習率0.60の指数重みで、最新60%、1つ前24%、2つ前9.6%相当を反映する。
  1件の角度更新は最大±13.5度。移動が0.02 IPS相当未満なら角度を学習しない。
  距離比は0.5～2、1回の予測距離更新は前回の0.85～1.3倍に制限する。
  距離の基準は更新するため、古い初回距離の倍率上限に張り付かない。
  これらは数値的な安定化の初期設定であり、実機精度を保証する値ではない。
- 学習データは別の `balance-chart-learning-v1` にversion 2形式で保存する。
  旧version 1の未確認データは実調整と推定せず、学習対象から除く。測定・調整・回転設定は保持する。
  保持中の測定履歴から再構成するため、再描画で件数は増えず、編集・削除も反映する。
  削除で新しく隣り合った結果は、新しい調整の実測として学習しない。
- 調整登録時の予測は固定して保存する。既存履歴から作る予測は
  `prospective: false` として区別する。
- 六角形の自動回転は、学習済み角度がなければ、実調整未指定でも直近の単一調整と前後測定を使用する。
  LINK赤・青、TAB紫は対象色と調整種別を独立して参照し、未指定履歴を学習・確定済みデータへ追加しない。
- LINKは両点が0.20以内なら両点改善を優先し、通常は両有向線が0.20以内を通る組を優先する。
  候補内では予測中心距離の最大値、合計の順に比較する。両線通過がなければHOV最接近距離を先に比較する。
  手動・学習不足時も同じ選択順位を使い、既存の移動距離予測を維持する。
  TABの評価対象は既存どおり巡航のみ。TAB→HOVの実測モデルも別に保持する。
- 学習リセットは測定・調整・回転設定を削除しない。
  リセット時点の連続結果を再学習せず、その後の新しい結果から学習を再開する。
- 手動補助は自動から手動に切り替えた後、実際に回転した色だけを記録する。
  実測モデルへの補助角度は小さく制限し、実測数が増えると影響を弱める。

開発者コンソールで `balanceChartLearning.inspect()` を実行すると、
モデル、実測ベクトル、記録時の予測、誤差、候補の予測終点・改善量、
フォールバック理由、保存エラーを確認できる。調整を自動で確定する機能はない。
