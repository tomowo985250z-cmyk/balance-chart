# 手動方向・確定予測・画面別ロックの検証

## 対象動作

- LINK/TABの手動UP／DOWNに、HOV・巡航それぞれのガイドと予測点が連動する。No.と量を保持し、取消・再描画・画面往復・再読み込みにも対応する。
- 基本は「結果入力→調整→結果入力」。LINKで追加したらLINKだけをロックし、TABで追加したらTABだけをロックする。未調整の画面では、直前の確定予測を起点に続けて調整できる。段階数の選択や終了操作は設けない。
- 新しい実測結果を登録すると両方のロックを解除する。入力された色は新しい実測を優先し、未取得の色は直前の確定予測を使う。予測値を実測や学習データへ登録しない。
- 調整内容と保存済み確定予測を、追加時に結果欄へ表示する。新しい結果の登録や未確定操作で、過去の確定座標を上書きしない。画面別の重複防止は、過去の履歴件数と分離して管理する。
- 最新の確定調整だけに「編集」を表示する。専用ダイアログでNo.・方式・方向・量を変更し、保存時にその履歴と予測・ガイドを更新する。過去の確定履歴は編集できず、キャンセルでは元の内容を保つ。他方が確定済みの場合は、その方式への変更による重複を防ぐ。通常の操作ロックは外さない。
- 予測情報を持たない旧保存形式も、最新の記録1件だけを編集対象にする。キャンセルでは保存形式を変更せず、保存時だけ予測情報を追加する。
- HOVのみ・巡航のみ・両方あり・測定なしを区別する。HOVのないLINKは自動候補を作らず、利用者が選択したNo.と方向だけを既存の方向線・距離推定で表示する。
- LINK/TABとも赤をHOV、青を巡航として表示し、320/375/390/430pxで横にはみ出さない。

## 維持する計算・選択規則

`learning.js`と`link-ranking.js`は変更しない。距離推定は既存の学習値・実測・参考距離を優先し、それらがある条件の計算結果を維持する。追加済みのTAB HOV参考表示と不足時の表示用係数補完は、実測・学習記録を作らない。LINKの順位評価に表示専用係数を渡さない。

TABの巡航がある場合は、従来の巡航候補を選択してから同じNo.・方向のHOVガイドを表示する。UP／DOWNの自動選択優先順位変更は保留する。

| スイート | 確認内容 |
| --- | --- |
| `independent-flow` | LINKのみ・TABのみ・両順序、画面別ロック、重複確定防止、新しい実測での両ロック解除、3回の反復、色別起点、即時結果表示、全確定ドットの保持、保存・復元 |
| `latest-confirmed-edit` | 最新1件の編集、キャンセル・Esc、履歴更新、方式変更、他画面の継続、ロック維持、予測・ガイド再計算、実測・学習の不変性、保存・復元 |
| `manual-direction` | 両方式、手動・学習待ち・学習済み、3候補、通常起点・確定予測の引き継ぎ、方向ボタンクリック、予測点・ガイド・距離・描画座標の一致 |

| `confirmed-carry` | 色別の実測更新・確定予測引き継ぎ、反復サイクル、実測と学習の保持 |
| `confirmed-results` | 調整内容の結果欄への即時反映、保存済み予測値、下書きの混入防止、片色・欠測・削除 |
| `tab-forecast`, `all-guide-dots` | 各No.・方向・量でのHOV/巡航表示、ガイドON/OFF、確定予測 |
| `reference-forecast` | 既存推定値の維持、不足時の係数と根拠、実測・学習・順位の保持 |
| 既存スイート | 学習、候補順位、調整量、保存・復元、入力、回転、表示の回帰 |

Windows Edgeの一時プロファイルで、通常のブラウザ保存領域から分離して実行する。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./tests/run-browser-tests.ps1 -Tests all
```

`output/`内の実行ログ・画面画像・作業前コピーはローカル検証用で、commit対象に含めない。テスト用HTMLと`.test.js`は継続的な回帰確認に必要なソースとして管理する。実機Safariの確認は別途必要。
